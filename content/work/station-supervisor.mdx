## The problem

Each production line runs its own mix of equipment, but the software that
supervises a line and the workers that talk to individual machines shouldn't
be six different codebases. Without a shared topology, every new line is a
new one-off, and every fix has to be re-applied by hand everywhere it
matters.

## What I built

A three-tier topology: a station supervisor per line, a set of config-driven
plugin workers underneath it, and the line hardware those workers talk to.
The plugin workers are configuration, not code — adding a new machine type to
a line is a config change, not a new service. The whole stack is
containerized and deployed through a shared monorepo deployment model across
all six lines and both sites.

I consumed the Kubernetes platform here rather than building it — the
containerization, the service topology, and the config-driven plugin model
are what I own.
